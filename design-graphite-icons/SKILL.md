# 石墨黑白橙图标风格

保持风格一致，不重复某一套图案。根据每个场景的含义选择主体，用简洁轮廓与克制的明暗表达功能，再按实际载体应用配色。

## 先确定使用条件

- 读取 [配色规范](references/palette.md)，确认已有设计系统和用户明确约束。
- 明确图标表达的对象、动作或状态，以及它出现的位置、实际显示尺寸、背景、是否需要交互。
- 从项目内容中寻找答案；只有缺失的信息会影响结果时才追问。不要让用户替设计师选择路径坐标或渐变参数。
- 区分独立彩色图标、界面图标、单色模板与成套图标。它们共享视觉语言，但不强制使用同一底板、画布或材质。
- 用户已有图案或选定方向时，保留语义与识别特征；不要重新套上别的产品的图案。

## 通用视觉语言

### 含义先于形式

- 优先采用所在领域已经易于辨认的视觉隐喻，先让人理解含义，再处理设计感。
- 控制抽象程度。简化不等于隐藏含义；不依赖解释才能辨认。品牌图形可更有个性，但仍要符合明确需求。
- 不预设必须使用某种物件、字母、几何图形或叠放方式，也不因为它们在一次设计中不好看就永久禁用。
- 保留一个清楚的视觉焦点。所有附属元素都要贡献含义，不能为了用上强调色再加一个点。

### 轮廓与比例

- 以简洁、连续、有明确重量的轮廓建立识别度；删去缩小后只剩噪声的内部细节。
- 按尺寸进行光学校正，不机械等比缩放。调整细线、间隙、小孔与局部留白，避免小尺寸糊成一块。
- 以视觉重心对齐，而不是只按数学包围盒居中。给轮廓留足空间，不规定所有图标共用相同坐标、角度或占比。
- 成套图标保持一致的网格、视觉重量、描边、端点、转角、透视与细节密度；必要时进行逐个光学校正。
- 不混用线性、实心和立体风格作为同一套的无理由变化。

### 颜色与质感

- 使用非纯黑的石墨深灰、银白与辅助灰建立主次，暖橙只承担少量强调。按配色规范适配背景，不强制每枚图标都出现三种颜色。
- 自行绘制时不用纯黑底板、轮廓或阴影。允许操作系统对单色模板或高对比模式进行着色，不为维持品牌色破坏系统适配。
- 默认先做干净的平面形态；仅在大尺寸、独立展示且确有层次需要时加入柔和渐变、少量厚度与接触阴影。
- 保持轻微立体，不使用装饰性辉光、彩虹反射、重玻璃、夸张透视或强塑料高光。
- 图标的色彩不能成为理解操作或区分状态的唯一线索。

## 根据载体适配

| 场景 | 保留的风格 | 必须适配的部分 |
| --- | --- | --- |
| 独立 App、产品或入口图标 | 清楚主体、石墨与银白主次、少量暖橙；可有轻微层次 | 使用平台要求的画布、安全区、遮罩与资源格式；仅需要时加底板 |
| 网页、移动端 UI、导航、工具栏 | 简洁、统一视觉重量、语义直接 | 优先平面；按最终像素网格绘制；不要给每个符号加圆角方块或阴影 |
| 菜单栏、系统托盘、模板或单色图标 | 轮廓、比例和可辨认的内部留白 | 使用平台的单色与模板机制，通常不保留橙色，不烘焙固定背景 |
| 状态、提示或交互图标 | 清晰含义与一致笔触 | 优先保留系统或产品既有的成功、警告、危险及选中语义，不把所有状态改成橙色 |
| 文件类型、分类、品牌图形 | 简练、有区分度的主体与受控细节 | 选择与目标含义对应的符号；不固定使用同一种物件或组合 |

同一风格不等于同一图案，也不等于在所有场景使用同一配色数量或立体程度。

## 工作流程

1. 先确定语义、载体和最终尺寸，建立最小可辨认轮廓。
2. 在真实背景上应用配色，先核对主次和对比度，再考虑质感。
3. 首轮默认同时设计 4—6 个版本，在同一轮交付中提供选择；用户明确指定数量时按其要求执行。让版本在语义、轮廓或构图上确有差异，保持风格一致，不只改颜色或旋转角度凑数。已有选定稿时不重新发散。
4. 为每版编号，在统一尺寸与背景下并排展示，并提供实际小尺寸预览；简述各版差异，不只给文字描述或零散文件，让用户能直接比较。
5. 明确请用户选择最终图标或提出修改意见。可以给出推荐，但不得替用户决定；收到选择前仅交付候选，不擅自定稿、替换正式资源或接入工程。
6. 用户选定后只细化所选方向；需要组合或再出版本时按反馈调整。收到“太抽象”时增强识别特征；收到“太复杂”时删去次要含义和装饰。
7. 在实际使用尺寸与场景中预览定稿；界面图标同时检查浅深主题及相关交互状态，不只展示放大的白底稿。
8. 按需求交付所选方案的可编辑矢量和必要位图。由载体决定 viewBox、导出尺寸、透明度和命名，不把某一种资源规格强加给其他场景。
9. 只有用户选定方案并要求工程接入时才修改正式资源；平台打包、签名与缓存处理交给相应配置流程，不混进风格规范。

## 验收

- 不看说明也能理解图标在当前语境里的主要含义。
- 成套图标的笔触、重量、留白与细节密度一致，相关图标之间有足够区分。
- 在最小实际尺寸下轮廓清楚，没有消失的关键线条、堵塞的留白或无效装饰。
- 在目标背景、主题与状态下具有足够对比；必须理解的界面图形与邻近背景通常至少达到 3:1，相关无障碍标准优先。
- 单色、透明底和平台强制着色场景仍能工作，不依赖橙色或阴影才能识别。
- 输出格式和尺寸符合载体要求；没有把预览截图当作可编辑或生产资源。
- 如实说明未检查的平台、主题或尺寸，不把风格指导当作所有设备已验证的保证。
